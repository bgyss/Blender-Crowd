# Blender Crowd 1.0 compatibility and upgrade policy

## Supported data

Blender Crowd 1.0 reads Cache Manifest v1, Project IR v1, Authorable Project
IR v2, Behavior Graph v1, Decision Trace v1, and Override Layer v1/v2. A
complete cache must validate every declared chunk, agents table, and optional
behavior-event file before it is attached. Canceled, incomplete, corrupt,
older, and newer caches are never presented as authoritative playback.
When a scene has a Crowd project, the cache source hash must also match the
currently compiled project; a mismatch is stale and is rejected before display.

## Upgrade and downgrade

Project IR v1 is migrated in memory to Authorable Project IR v2 during M2/M3
authoring. The original scene data remains the source of the generated payload.
There is no downgrade writer from v2 to v1. Future cache or project schema
versions must supply a checked migration fixture and preserve the 1.0 reader
behavior, or fail with an actionable unsupported-version diagnostic.

## Recovery

Inspect a cache through **Crowd Workflow → Inspect Health**. A cache with a
readable prefix remains a recovery artifact only; rebake before playback or
render. On reload, cache attachment is revalidated and stale geometry is hidden
when no complete authoritative cache is available. See the
[recovery guide](../user/m3-production-recovery.md) for the operator workflow.

## Compatibility tests

`cargo test -p crowd-cache` exercises complete, canceled, incomplete, corrupt,
and unsupported-manifest paths. The archive-level M3 runner additionally checks
that the released package contains this policy and its recovery test.
