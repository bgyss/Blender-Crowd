# Blender Crowd 1.0 release checklist

The following is a release stop list, not a list of aspirations. A candidate
remains unaccepted until every required item has immutable evidence.

- [ ] Build each support-matrix archive with `scripts/m3-build-release.sh`.
- [ ] Build from a clean committed source tree; the archive auditor rejects dirty provenance.
- [ ] Preserve `SHA256SUMS`, archive audit, SBOM, and provenance alongside each archive.
- [ ] Sign archives where the platform/release channel supports signing; document the identity and verification command.
- [ ] Run `scripts/m3-acceptance.sh --archive …` on every claimed support-matrix row.
- [ ] Run M3 failure drills: canceled, corrupt, stale, older, newer, missing-asset, moved-project, and save/reload cache cases.
- [ ] Record measured performance, memory, cache, playback, render, and package-size budgets against the fixed baselines.
- [ ] Complete license/SBOM review and publish the known-limitations and recovery policy.
- [ ] Obtain two independent evaluator records per claimed platform.
- [ ] Publish the dated acceptance report only after every preceding item passes.

Do not ship around data loss, cache misidentification, unsupported linkage,
nondeterministic decisions, or an unbounded crash.
