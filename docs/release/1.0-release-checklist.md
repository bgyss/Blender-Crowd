# Blender Crowd 1.0 release checklist

The following is a release stop list, not a list of aspirations. A candidate
remains unaccepted until every required item has immutable evidence.

- [x] Build each support-matrix archive with `scripts/m3-build-release.sh`.
- [x] Build from a clean committed source tree; the archive auditor rejects dirty provenance.
- [x] Preserve `SHA256SUMS`, archive audit, SBOM, and provenance alongside each archive.
- [x] Decide signing applicability for the release channel and record the integrity controls.
- [x] Run `scripts/m3-acceptance.sh --archive …` on every claimed support-matrix row.
- [x] Run M3 failure drills: canceled, corrupt, stale, older, newer, missing-asset, moved-project, and save/reload cache cases.
- [x] Record measured performance, memory, cache, playback, render, and package-size budgets against the fixed baselines.
- [x] Complete license/SBOM review and publish the known-limitations and recovery policy.
- [x] Publish the dated acceptance report only after every preceding item passes.

Independent evaluator records are an M7 ecosystem-integration gate. They are
valuable post-1.0 evidence, but are deliberately not a 1.0 release stop.

Do not ship around data loss, cache misidentification, unsupported linkage,
nondeterministic decisions, or an unbounded crash.
