# Blender Crowd 1.0 accessibility review

Scope: Blender 5.2 LTS on macOS Apple Silicon, using the stock Properties editor
and stock Blender themes. The 1.0 extension draws no custom pixels, registers no
custom keymap, and performs no manual hit testing; focus visibility, keyboard
navigation, target sizing, contrast, theme adaptation, text scaling, and screen
reader exposure therefore use Blender's native controls and accessibility tree.

The primary Crowd Workflow panel presents stage, selection, next action,
progress, cache health, recovery, and diagnostic history before the closed
Advanced panel. Every operator has a readable label and description. Raw JSON
authoring fields are confined to the explicitly labeled Advanced panel and are
not needed for the documented 1.0 workflow. Status is never conveyed only by
color: severity, cache status, workflow stage, and recovery action are text.

The archive test `tests/blender/test_m3_accessibility.py` enforces those
extension-owned invariants. Blender itself controls native focus rendering,
theme contrast, scaling, and assistive-technology support; host limitations are
not represented as extension capabilities. M7 retains real-user accessibility
studies and cross-version Blender convention review.
