## Exactly one threshold change is load-bearing

The thresholds were recalibrated on 2026-08-17 (see the file's `basis`). Against
the *previous* numbers this run would have scored:

| Check | Measured | Old limit | |
| --- | ---: | ---: | --- |
| S1 `penetration_agent_ticks_per_agent_tick` | 8.272e-7 | 1e-6 | pass |
| S2 `penetration_agent_ticks_per_agent_tick` | 1.859e-6 | 1e-5 | pass |
| S2 `mean_penetration_depth_fraction` | 3.368e-8 | 1e-7 | pass |
| **S1 `mean_penetration_depth_fraction`** | **1.349e-8** | **1e-9** | **FAIL** |

So the pass turns on one limit: S1's severity bar. That bar was derived from a
10K measurement of **one contact**, with **zero** contacts at 1K, and it is
breached at 40K as well — so it was demonstrably unsound before this run
existed, independent of its result. The other three changes are not what
produced the pass; one of them (S2's contact rate, 1e-5 to 5e-6) is a
**tightening**.

This is stated plainly because "recalibrate, then pass" is the shape of moving
the goalposts, and the distinction has to be auditable rather than asserted.

## Scale evidence

Measured `distance_travelled_m` is 214,934,601 m — 2,149 m per agent, against
670 m at 10K, and the first time this fixture's exposure has been measured
rather than inferred. The stall rate that replaced `stalled_agent_share` is
0.504/km (S1) and 0.493/km (S2), against 0.160 and 0.220 at 10K and 0.274 and
0.292 at 1K. The metric is non-monotonic across scales, so a regression claim
has to name its baseline.

Contact, by tier, with the exposure defect fixed:

| tier | agent-ticks | contact-observed | ratio | contacts | rate |
| --- | ---: | ---: | ---: | ---: | ---: |
| S1 | 530,735,184 | 530,735,184 | 1.000 | 439 | 8.272e-7 |
| S2 | 4,751,995,077 | 2,376,042,238 | 0.500 | 4,417 | 1.859e-6 |

S2's observed share is exactly 0.500, as it is at every other scale: the
background tier can only be seen overlapping on the ticks it perceives, and the
rate now divides by those ticks. S2's rate here is **twice** what the same run
would have reported before the fix, so it must not be compared with the S2
figures in the two earlier 100K reports.

S1 keeps a 2.2x contact advantage over S2 at this scale (ratio 0.445), matching
the 0.449 measured at 40K. The advantage plateaus from about 20K rather than
decaying toward parity.

`deep_penetration_agent_ticks` is **non-zero for the first time**: 97
population-wide, an S2 rate of 4.082e-8. Every previous run at every scale
measured exactly zero, which is why it is reported and not gated. There is now
a measurement to set a bar from, and it should be gated once a second run
confirms it.

## Corrections to earlier findings

Two statements in the preceding report are revised by this run's data.

**"S1 agents never contact each other" was too strong.** It held at 10K, 20K,
and 40K, but the tier-blind expectation at those scales was 0.1, 0.9, and 6.5
contacts — only the 40K point was informative. At 100K there are **30** S1-S1
contacts against a tier-blind expectation of 43.9. Suppression is real but
partial (0.68x), not absolute.

**`penetration_episodes` is not meaningful for a tier on a sparse cadence.** S1
reports 439 contacts over 141 episodes, 3.11 ticks each. S2 reports 4,417 over
4,417 — exactly 1.00 — because an unobserved tick makes the agent look
non-penetrating and resets the episode flag, so one contact spanning observed
ticks is recounted each time. Only S1's episode figure can be read here. The
counter needs to hold its state across unobserved ticks; that is a follow-up,
deliberately not applied to the code this run was measured on.

## What this establishes, and what it does not

- 100,000 agents complete the fixture with every agent arriving, at 13.7
  simulated ticks per second, within every checked-in per-tier quality limit.
- The result is reproducible: same `final_state_hash` as two prior runs, from a
  named commit, with the runner checked in.
- It does **not** establish that the residual scale trend is understood. Both
  tiers' contact rates rise ~1.74x from 40K to 100K, equally, which points at
  scene geometry — agents per lane grow with the square root of population
  while density is held constant — rather than at the solver or the tier
  scheduler. No mechanism is proven.
- It does **not** revisit the 1M question. Contact rates rising ~1.74x per
  scale step would put a 1M run near these limits, so the next scale needs its
  own calibration rather than an extrapolation from this one.
