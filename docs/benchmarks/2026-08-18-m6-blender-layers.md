# M6 Blender physics and hero layer proof

Status: PASS on 2026-08-19 with normal macOS host Metal access.

This proof loads the current source add-on and a freshly built native wheel,
attaches deterministic M6 interaction, contact, physics-transition, and hero
support artifacts to a complete base cache, and exercises mute, remove, and
reload without rebaking.

## Verified boundary

The Blender layer operator requires an already attached complete Cache v1 and
uses its full `base_cache_hash` as the attachment identity. It rejects an
interaction layer or physics transition from another cache and rejects paired
motion whose request or participant set differs from the interaction layer.

The panel exposes:

- interaction and physics owners;
- both tick intervals;
- named paired contacts and contact ticks;
- interaction, motion, solver, and full cache-hash provenance;
- recovery and interaction/motion/physics/hero failure policies; and
- hero integration ID, declared solver, adjacent-cache policy, and supported
  render tiers.

The interaction artifact is lowered to one exact-tick native animation layer
per sparse edit. The physics transition is lowered to a native cached physics
handoff generated by `blender_crowd_native.simulate_physics_handoff`. M6
overlays have a dedicated playback list, so attaching or clearing them does
not replace an existing M4 stack.

## Host Blender result

Command:

```bash
scripts/m6-blender-test.sh
```

The runner built `blender_crowd_native` in release mode, unpacked the fresh
wheel into an isolated temporary site root, and launched Blender with the
current checkout on `PYTHONPATH` plus `--python-use-system-env`. Both Blender
processes used normal host access rather than the restricted automation
sandbox.

Result:

```text

M6 Blender physics/hero layers: PASS
```

Environment:

- Blender 5.2.0 LTS, build `fbe6228777e7`;
- macOS 27.0 build `26A5416b`, Darwin arm64; and
- current source add-on plus freshly built CPython 3.11+ abi3 arm64 wheel.

The lifecycle smoke baked a complete 10-agent/31-tick test cache, captured its
manifest SHA-256 and full base-cache identity, and generated matching
interaction and physics artifacts for two real stable IDs from that cache. At
tick 15 it observed clip IDs 42 and 43 only on the two targets. The third agent
remained byte-for-byte equal through attach, mute, unmute, remove, and reload.
Muting and removal restored both targets to their base records. Reload restored
the sparse edits. The cache identity and manifest SHA-256 never changed.

## RED/GREEN evidence

Before implementation, the host runner reached Blender and failed after its
existing debugger smoke with:

```text
AttributeError: Calling operator "bpy.ops.crowd.load_m6_layers" error, could not be found
```

The first GREEN attempt exposed a real compiled-bridge defect: viewport
`read_tick` composed layout layers, but `inspect_agent` reported base clip and
phase values. The bridge now inspects the same native composed layout state as
playback. `cargo test -p crowd-blender --quiet` passed 9 tests before the host
Blender lifecycle passed.

## Unsupported claims

- The Blender cloth declaration is a validated support boundary; this run did
  not execute or benchmark Blender cloth, hair, or Geometry Nodes deformation.
- The cached handoff uses the deterministic native reference integrator. It is
  not evidence for Blender rigid-body solver parity or arbitrary collision
  scenes.
- Contact evidence is loaded from a validated paired-motion artifact; this
  smoke does not regenerate skeletal interaction motion.
- The proof establishes cache isolation and target-only composition, not visual
  quality, artist usability, or production-scene performance.
