# M9 — Neural animation and operator validation

## Objective

Evaluate optional learned animation backends for promoted agents and prove that
independent operators can understand, direct, reject, repair, and replay advanced
agency and motion through the supported Blender interface. This milestone turns
the research and human-evidence tracks into production claims only when their
separate gates pass; it does not reopen accepted deterministic M6 behavior.

## Prerequisites

M6 is accepted, including its model-independent R0 request/response boundary,
deterministic paired-clip baseline, validators, sparse animation layers,
fallbacks, and automated Blender debugger smoke. R3 additionally requires the
M8 combat domain pack's semantics, assets, rights, and entertainment-only claim
boundary. Before any model or dataset is used, code, checkpoint, training data,
motion data, and redistribution terms must be reviewed and recorded.

## Track A — Neural animation research

1. **R1 — ARDY single-character constrained motion.** Prove packaging,
   canonical-skeleton conversion, retargeting, trajectory/constraint fidelity,
   provenance, editable sparse layers, deterministic replay, and model-absent
   fallback. This is not paired-reaction evidence.
2. **R2 — Online two-character reaction.** Compare independently reactive,
   jointly generated, and deterministic paired-clip baselines under held-out
   partner perturbations, explicit contacts, authored roles, and outcomes.
3. **R3 — Weapon interaction and combat domain pack.** Add M8-owned weapon and
   combat semantics, contact types, reversible outcomes, safe failure poses,
   and independently reviewable corrections without making physical-accuracy
   claims.
4. **R4 — Scheduled scale and production study.** Measure one, two, four, and
   sixteen concurrent interaction groups, queueing, cancellation, memory,
   worker failure/reload, cache reuse, correction, and supported tier mixes.

The Rust core remains authoritative for intent, roots, roles, contacts,
outcomes, event timing, validation, and fallback. A model proposes skeletal
motion only through the versioned M6 boundary; accepted output remains an
editable, removable, content-addressed layer playable without the model or
accelerator.

## Track B — Independent operator verification

Run the checked study protocol with clean release artifacts and participants
who did not implement the tested workflow. Cover state-machine, utility,
behavior-tree, motion/contact, interaction, degraded-evidence, and large-graph
navigation tasks. Record trace-to-node agreement, discovery and repair time,
wrong turns, intervention, layer/base-cache preservation, and whether the
participant understood unavailable lower-tier evidence.

This track evaluates both the deterministic M6 debugger and, when Track A has
an accepted backend, neural proposal/rejection/fallback controls. Automated
operator calls or Blender smoke tests prove execution only and cannot satisfy
the independent-user gate.

## Explicit exclusions

No per-agent per-frame LLM/VLM steering, model ownership of collision safety or
authored outcomes, unlicensed motion/checkpoints, hidden model or accelerator
playback dependency, reel-only quality claim, universal rig compatibility, or
claim that entertainment combat animation is martial, injury, or physical
simulation evidence.

## Required artifacts

- Frozen worker, model, checkpoint, configuration, skeleton-map, data-license,
  and output hashes for every claimed neural backend.
- Checked R1–R4 fixtures, baselines, validators, reports, and failure cases.
- Sparse-layer, cache-reload, model-absent playback, correction, removal, and
  unrelated-agent isolation evidence.
- Dated pseudonymous operator-study reports and redacted captures following the
  checked protocol.
- `scripts/m9-foundation-test.sh` and `scripts/m9-acceptance.sh` before any M9
  implementation is presented as executable; until then, no M9 runner exists.

## Acceptance criteria

1. R1 improves at least one predeclared quality dimension over deterministic
   baselines without failing hard contact, root, stability, licensing,
   provenance, editability, or fallback requirements.
2. R2 demonstrates bounded reaction latency, long-horizon stability,
   role/outcome fidelity, valid contacts, independently traceable participants,
   and improved blinded preference on held-out perturbations.
3. R3 preserves M8 domain ownership and proves its declared paired combat
   interactions, reversible outcomes, correction workflow, and safe fallback.
4. R4 publishes supported concurrency/tier limits with latency, throughput,
   memory, cache, cancellation, crash recovery, and model reload evidence.
5. Accepted caches replay and render without a worker, model, accelerator, or
   access to a contributor checkout.
6. Independent participants complete the deterministic debugger tasks using
   only the supported interface and node reference, with the required timing,
   recovery, and degraded-evidence records.
7. If neural controls are claimed, independent participants can inspect,
   reject, correct, fall back, and replay accepted output without mutating the
   base cache or unrelated agents.

## Validation and authorization boundaries

All model, data, accelerator, cloud, and participant-study work is inert until
explicitly authorized in the task that performs it. Set thresholds from checked
baselines before experiments. Keep local schema/fixture validation, realized
model runs, Blender playback, blinded preference, and operator evidence as
separate proof levels. Add exact commands to this contract, `AGENTS.md`, and
`README.md` only when the corresponding M9 runners exist.

## Definition of done and stop conditions

M9 is done only when all R1–R4 stages and the independent operator gate have
authoritative evidence. A later stage may remain unclaimed without erasing an
earlier result, but the milestone as a whole remains open. Stop if a model
becomes authoritative, provenance or rights are unresolved, playback requires
the model, a correction changes unrelated agents/base truth, or human evidence
is inferred from automation.
